# site-uptime-monitor

对指定站点做**定时健康探测**的外部探针。目的不是监控可用性，而是从多个云机房
产生**真实、多样来源的公网入向 HTTP 流量**，用于网络流量数据集的"正常类"采集。

## 采集对象

| 项 | 值 |
|---|---|
| 目标 | `http://47.242.176.36` / `https://47.242.176.36` |
| 频率 | 每 30 分钟一轮 |
| Runner | ubuntu-latest / windows-latest / macos-latest |
| 每轮请求 | 3 × 9 ≈ 27 次 |

## 每轮访问序列

1. `/`、`/about`、`/status`、`/docs/`、`/robots.txt`、`/sitemap.xml`
2. 一次随机路径的 404（正常用户也会打错地址）
3. 一次带表单的 `POST /admin/login`（失败的登录尝试）
4. 一次 TLS 握手（目标用自签证书）

请求之间插入 3–18 秒随机停顿，模拟人工浏览节奏；User-Agent 从 5 个真实浏览器
指纹中随机挑选。

## 为什么不用单机 cron

单机只有一个出口 IP，样本多样性不够。三个 GitHub Runner 分布在 Azure 不同机房，
天然是不同 ASN，IP 池还会随每次运行轮换。

## 注意

- 公开仓库的 Actions 分钟数不限；私有仓库每月 2000 分钟，本 workflow 约需 8600 分钟/月
- GitHub 会停用 60 天无提交仓库的定时任务，需要偶尔提交保活
- 仅用于探测自己的主机
